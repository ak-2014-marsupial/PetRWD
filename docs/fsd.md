# Feature-Sliced Design (FSD)

Цей проєкт використовує методологію **Feature-Sliced Design (FSD)** для організації коду. Це архітектурний підхід, який допомагає зробити великі проєкти масштабованими, тестованими та легкими у підтримці.

## Основні Шари (Layers)

Структура `src/` розділена на шари, кожен з яких має свою відповідальність:

1.  **`app/`**: Глобальні налаштування, стилі та провайдери. Тут ініціалізується додаток.
2.  **`pages/`**: Сторінки додатка. Це композиційні блоки, які збираються з віджетів та фіч.
3.  **`widgets/`**: Великі самостійні блоки інтерфейсу (наприклад, `AppShell`, `Header`, `Sidebar`).
4.  **`features/`**: Взаємодії користувача, які мають бізнес-цінність (наприклад, `ThemeSwitcher`, `FontSizePicker`).
5.  **`entities/`**: Бізнес-сутності та їх дані (наприклад, `User`, `Product`).
6.  **`shared/`**: Перевикористовуваний код, не прив'язаний до бізнес-логіки (UI-кіт, утиліти, хуки, сервіси).

## Ключові Принципи

### 1. Односпрямований потік залежностей
Шар може залежати тільки від шарів, що знаходяться нижче. Наприклад, `features` можуть використовувати `entities` та `shared`, але не можуть використовувати `widgets` або `pages`.

### 2. Слайси та Сегменти (Slices & Segments)
Кожен шар (крім `shared` та `app`) розділений на **слайси** (логічні модулі). Кожен слайс містить **сегменти**:
- `ui`: Візуальні компоненти.
- `model`: Бізнес-логіка, стейт.
- `lib`: Допоміжні функції.
- `api`: Запити до сервера.

### 3. Public API (index.ts)
Кожен слайс повинен мати файл `index.ts`, який є його "публічним вікном". Тільки те, що експортується через цей файл, може бути використано в інших частинах додатка. Це запобігає заплутуванню внутрішніх деталей реалізації.

## Переваги для цього проєкту

- **Масштабованість:** Нові фічі додаються як нові слайси, не порушуючи роботу існуючих.
- **Передбачуваність:** Чітко визначені місця для кожного типу коду.
- **Легкість рефакторингу:** Модулі ізольовані, що зменшує ризик регресій.
