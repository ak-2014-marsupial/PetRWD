# Синхронізація Конфігурації (JS -> CSS)

Цей документ пояснює, як константи, визначені в TypeScript, стають доступними в CSS-файлах.

## Проблема
В сучасній веброзробці часто потрібно мати спільні значення для логіки (JS) та стилів (CSS). Наприклад, ширина сайдбару потрібна в CSS для лейауту і в JS для розрахунку відступів або анімацій. Дублювання цих значень призводить до помилок.

## Рішення: Single Source of Truth
В нашому проєкті єдиним джерелом істини є файл `src/app/config/appConfig.ts`.

### Технологічний стек
1.  **`jiti`**: Дозволяє імпортувати TypeScript файли (`.ts`) безпосередньо в оточення Node.js (наприклад, у конфіг PostCSS) без попередньої компіляції.
2.  **`postcss-simple-vars`**: Плагін для PostCSS, який замінює змінні формату `$VARIABLE` на їх реальні значення під час збірки.

## Як це працює

1.  **Експорт конфігу**: Всі змінні описані в об'єкті `APP_CONFIG`.
2.  **Міст у PostCSS**: У файлі `postcss.config.js` ми використовуємо `jiti` для імпорту цього об'єкта.
3.  **Плагін**: Об'єкт `APP_CONFIG` перетворюється на плаский список змінних (наприклад, `LAYOUT: { SIDEBAR: '20rem' }` перетворюється на `$LAYOUT__SIDEBAR: '20rem'`) і передається в `postcss-simple-vars`.

## Приклад використання

**TypeScript (`appConfig.ts`):**
```typescript
export const APP_CONFIG = {
  LAYOUT: {
    SIDEBAR_WIDTH: '20rem'
  }
}
```

**CSS (`AppShell.module.css`):**
```css
.sidebar {
  width: $LAYOUT__SIDEBAR_WIDTH;
}
```

Під час збірки Vite (через PostCSS) перетворить це на:
```css
.sidebar {
  width: 20rem;
}
```

## Переваги
- **Відсутність дублювання**: Змінюєте значення в одному місці — воно оновлюється скрізь.
- **Типізація**: Ви використовуєте TypeScript для опису ваших констант.
- **Продуктивність**: Ніяких розрахунків у рантаймі через JS, чистий стаціонарний CSS після збірки.
